# App A producer replacement qualification

This is execution preparation, not a GO, native result or unfamiliar-operator
rehearsal. The template app-replacement.template.json has execution_go=false
and unresolved inputs. The final composed source, native build receipt, enabled
release, wrong-release artifact, new importer-binding helper, intended runbooks
and independent driver review must exist before root binds an execution config.
Set runbook_root to the intended qualified operator-document source, with exact
hashes of its P2, App A and operator runbook files. Do not silently substitute
private producer instructions when published/curated documentation differs.
No VM or build is launched by this preparation.

## Vehicle and exact inputs

Use the admitted disposable QEMU VM, with inner TCG and primary IDE for
this occurrence. Preserve the chosen environment and fixed native/CLI acceptance
criteria. This driver does not qualify KVM performance or a different controller.
Run under the existing finite durable system unit, with KillMode=control-group,
its actual INVOCATION_ID and recorded RuntimeMaxUSec. Bind the unit properties
hash, original hard end, VM machine ID, unique run UUID, evidence/private paths
and named custodian before launch. The driver refuses a hard end more than four hours ahead and refuses to start
a phase without 120 seconds of cleanup reserve. These are upper/reserve checks;
they do not prove that remaining time is sufficient for this chain. Root must
forecast construction and recovery against the actual remaining admitted unit
window before GO. No arbitrary minimum runtime is inferred from these checks.
The durable unit's independent limit owns foreground canonical tool children;
this script is not a supervisor or a new resource mechanism.

Root owns storage admission: measure free blocks/inodes on both host filesystems
and the VM destination, reconcile other tenants and total expected construction,
and retain the 60 GiB reserve. Forecast the original image, private point, wrong
replacement and correct replacement (four full 128 MiB images), temporary canonical
importer/selection ISOs, kernel-run build products and bounded captures together.
Record actual allocation and retire only exact reproducible objects after custody
and review dependencies end. This driver preserves failed images, point bytes and
supplied keys; it does not decide their disposal from a successful test.

The selected release is the actual nominated private-source B: a complete

Provide the admitted campaign-owned operator client private key and its pinned

## Invocation and observable chain

After independent review and exact runtime binding, clear unresolved_inputs in
a new config and set its explicit execution_go. Use a fresh private and separate
public evidence directory, both outside the source and release inputs:

```sh
python3 -I -B -X pycache_prefix=PRIVATE/python-cache scripts/app-replacement-qualification.py --config ADMITTED.json --private-work PRIVATE --evidence EVIDENCE
```

PRIVATE is an absolute path; use the same path in the fresh external Python cache
prefix and --private-work. The driver and its Python children isolate cached code
outside source using the existing external-cache pattern.

The driver performs this one ordered chain with no retry or fallback:

1. Verify source, runbooks, compatible selected/wrong-release artifacts, native receipt, configuration,
   public host inputs, unit and namespace. Install the selected release through canonical release.py,
   configure it through release.py reconfigure, and check actual installed App A
   bytes and configuration before boot.
2. Fetch and read back the maximum 16,384-byte body and exact receipt. Halt cleanly,
   take the documented strict recovery point and retain its reported pin outside
   the point. Independently validate body, receipt, configuration and logical host
   identity in that point.
3. Boot the original again, write/sync/read a known post-point marker, then start
   another freshly attested fetch. Observe its actual decrypted GET and the held
   partial response while its SSH and bound QEMU are still live. Kill only that
   exact owned QEMU Popen. Retain its failed image and record the actual point-to-
   stop monotonic interval and committed marker. This proves a network-held
   in-flight interruption, not a pre-rename filesystem interruption.
4. A dead QEMU cannot promise remote TCP EOF. Close only the exact remaining
   owned peer socket locally after QEMU is terminal; record that origin explicitly.
   Do not reinterpret local closure as native peer receipt or remote EOF. Keep the
   listener and the complete raw peer records for the replacement.
5. Restore the point into a fresh wrong-boot destination. Launch the pinned wrong-release ISO
   against the selected release, require one exact release_mismatch refusal, no listener
   and no automatic reset, and preserve that failed image. Do not select/repair
   it in place.
6. Restore the selected release from the externally pinned point into another fresh destination.
   Require exact declared site state, retained host identity, old app body/receipt/
   configuration and the known post-point marker's own cat-not-found result.
   Sample/attest the new boot and perform a new maximum fetch. Write/sync a new
   application file, halt, boot the same replacement again, sample its fresh boot,
   read both old/new bundles and the new write back, and halt cleanly. Compare
   exact declared state, including new publication directories and absence of
   extra staging residue. Original failed images and point metadata must remain
   unchanged.

Existing P2 corruption/wrong-point negative cases remain their own qualification;
this driver does not duplicate or replace them. A generic P2 filesystem PASS is
not an App A case result. CLI copy/restore completion is not served recovery.
Any failed command, input mismatch, incomplete case order or cleanup failure
keeps RESULT.json FAIL. A source or receipt changed during the sampled checks
also refuses; transient concurrent mutations are outside that sampled guarantee.

## Checkpoint, evidence and follow-up

The first event records exact source, runtime unit/invocation, host, PID, paths,
terminal record and the next authorized reconciliation. Per-command intent and
terminal events retain real CLI exits; serial, SSH, receipt/body, catalog and
launch evidence stay in the separate evidence root. The point and seed-bearing
images remain private, with the configured custodian and concrete retirement
condition. Supplied private keys are retained for their named owner; the driver
uses no ambient agent, creates no keys and performs no broad cleanup. If the
unit disappears without RESULT.json, reconcile that same producer and its exact
private objects before restarting or replacing anything.
