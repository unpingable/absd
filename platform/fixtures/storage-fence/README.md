Writable guard v1 golden sectors. Each file is exactly 512 bytes: the ASCII line `absd-writable v1 STATE\n`, where STATE is fresh, dirty or clean, followed by zero padding. Rust and Python independently encode against these vectors. Missing, truncated, nonzero-padded and unknown-version records refuse writable entry. Only fresh, exclusively owned image construction seeds fresh; runtime never creates or repairs the record. Full transition and authority rules are documented beside the recovery ledger.

Operator-authorized resume slot v1 golden sectors (`resume-v1-*.bin`, coordination record #63; docs/WRITABLE-ENTRY.md "Operator-authorized resume"). Each is exactly 512 bytes. `resume-v1-none.bin` is the seeded slot: the ASCII line `absd-resume v1 none\n` followed by zero padding. `resume-v1-record.bin` is one authorization record: `absd-resume v1 id=<32 hex> fs=<16 hex> seq=<n> image=<64 hex> ledger_seq=<n> ledger_boot=<32 hex> previous=failed|not_ready time=<unix s> fnv=<16 hex>\n` zero-padded, where `fnv` is FNV-1a 64 over the preceding text of the line. `resume-v1-torn-40.bin` and `resume-v1-torn-200.bin` are the record's first 40 and 200 bytes followed by zeros: a torn sector write, refused as corrupt by both readers. Both encodings share the 15-byte prefix `absd-resume v1 `; anything else at the slot is corrupt (`RECOVERY STATE REFUSED reason=resume_corrupt` in the guest, `corrupt-slot` on the host). Rust (`fsd/src/resume.rs`) and Python (`scripts/storage_fence_state.py`) independently match these vectors. Only the fresh-image constructor seeds `none`; the operator act writes a record; the next serving boot consumes it back to `none` as its first device write; `recover --revoke` rewrites `none`.
