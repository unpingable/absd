# Cases of cports/cases.tsv whose ABSD result differs from Linux, each with its
# catalog class and id (docs/C-PORTABILITY-ASSUMPTIONS.md). Tab-separated:
# NAME CLASS: reason. A listed case must really differ, and its ABSD result must
# equal the contract's stated refusal. Probes (ROUTE probe) are never compared and
# never listed here. Final after the Stage 2 run (2026-10-12,
# docs/c-ecosystem-20261010/posix/receipts/matrix-full.log): every entry below was
# observed as stated, except lua.all and sqlite.temp-nomem, observed in the candidate 2
# run (d529ddbe, kernel 5a29fba); sqlite.excl-concurrency-loss is judged as a scenario.
sqlite.home	NATIVE SEMANTIC MISSING: no user database: the identity is synthetic (SPEC A8, CPA-013) and Picolibc's getpwuid returns NULL because ABSD has no /etc/passwd (DEMAND.md, getpwuid row); with the session environment empty and HOME unset (SPEC A20, never manufactured; CPA-037, IRRELEVANT POSIX ASSUMPTION, recorded per case) the shell says "cannot find home directory; cannot read ~/.sqliterc" on stderr and continues; the Linux reference finds its user's home through the host passwd database. The other SQLite cases name an empty init file (-init empty.sqliterc), which both systems read alike (WORKAROUNDS)
sqlite.system	NATIVE SEMANTIC MISSING: system() is refused (ENOSYS), no command processor (CPA-003)
sqlite.readonly	NATIVE SEMANTIC MISSING: a read-only connection's first lock is a byte range, refused EINVAL (SPEC A10), so SQLite reports a disk I/O error; Linux answers (CPA-009)
sqlite.excl-concurrency-loss	NATIVE SEMANTIC MISSING: SQLite's unix-excl single range lock mapped to the native whole-file exclusive lock, a declared consumer-specific divergence admitted only by the owner (SPEC A10); the loss against the default unix VFS is that readers are refused while a writer holds the database (CPA-008)
posix.modes	NATIVE SEMANTIC MISSING: the only permission state is the read-only flag; 0600/0755/directory modes are EPERM, mkdir's mode is not applied (0644 reported), a mode without owner write is EPERM with nothing created, and a file has no execute permission (access X_OK EINVAL) (CPA-014, CPA-040)
posix.dirwrite	NATIVE SEMANTIC MISSING: access(dir, W_OK) is a documented refusal (ENOSYS) until the mount-authority query lands (SPEC A11, A19); no probe file is created (CPA-002)
posix.lock	NATIVE SEMANTIC MISSING: locks are per handle and whole-file; two descriptors in one process conflict; ranges, F_GETLK and F_SETLKW are refused EINVAL (SPEC A10) (CPA-011, CPA-008, CPA-009, CPA-034); the one SQLite unix-excl request (F_WRLCK at 0x40000002 for 510 bytes on a read-write descriptor) takes the native exclusive whole-file lock, so the other descriptor's later shared lock is EAGAIN (SPEC A17, consumer-specific)
posix.refusals	NATIVE SEMANTIC MISSING: no command processor, signals, resource usage, file times, host name, links or ownership (CPA-003, CPA-004, CPA-017, CPA-016, CPA-025, CPA-015, CPA-013)
lua.all	NATIVE LIMIT (kit contract 2, 3; CPA-060): all.lua's locals.lua stack-overflow test needs ~48 MB of live heap on glibc; the 32 MiB heap window refuses it with "not enough memory" (status 1) and the suite stops there (judged by limit-prefix: stdout equal to Linux through the last progress line, stop file locals.lua, the message, non-zero status); constructs.lua, cstack.lua and later files never run. Linux stops later, at files.lua:8 with the empty environment.
sqlite.temp-nomem	NATIVE LIMIT (SPEC A18; CPA-060; CPA-049): the sort past the 32 MiB heap window is the declared SQLITE_NOMEM ("Error near line 10 of temp-nomem.sql: out of memory") and the shell continues ("still running|1"); after the R16 repair the later statement in the same process also succeeds as on Linux (the former RUNTIME defect, pinned until candidate 2); Linux sorts the 40000 rows. Pinned byte for byte.
