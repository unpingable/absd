# RTL8125B (10ec:8125, XID 641): firmware-free bring-up

coordination record #109, lane `lane/rtl8125-109`. Development evidence on reference_host's
second RTL8125B passed into a KVM guest (`reference_host-vfio`), not hardware_fixture hardware
qualification. Nothing here is selected by a default boot.

## Source and licence

Register offsets, bit values and sequences come from OpenBSD `if_rge.c`
v1.48 and `if_rgereg.h` v1.20 (ISC, Copyright Kevin Lo), kept at
`archived-occurrence` with SHA-256 sums. The one
derived file is `src/rtl8125.rs`: it carries the ISC notice and has its own
`provenance.toml` entry. `rtl8125_pci.rs` (PCI admission) and
`rtl8125_device.rs` (MMIO, DMA memory, boot entries) follow this kernel's
I219 backend and contain no rge code. Linux r8169 was not consulted.

The MAC loopback bits are not in rge. They are the TXCFG LBK1:LBK0 field
(bits 18:17, `01` = MAC loopback) of the RTL8169 family's transmit
configuration register, as Realtek's RTL8169 datasheet describes it. That
the 8125B keeps the field is a hypothesis S3 tests.

## Register model (8125B as rge drives it)

- **BARs.** BAR0 is I/O (unused). BAR2 (config 0x18) is a 64-bit memory BAR
  holding the 64 KiB register window; rge falls back to BAR1, which this
  part does not have. BAR4 is the MSI-X table (unused). Admission checks
  BAR2's type and 64 KiB alignment but does not size it (a sizing write can
  disturb a live device), as `i219_pci` does.
- **Revision.** `TXCFG (0x40) & 0x7cf00000`. `0x64100000` is the 8125B
  (rge `MAC_R25B`), the only value admitted. Every other value, including
  the original 8125 (`0x60900000`) and the 8125D/8126/8127, is refused.
- **MAC address.** IDR bytes at 0x00..0x05 (the current station address)
  and `ADDR0/ADDR1` (0x19e0/0x19e4), which rge copies into IDR. The probe
  reports both and does not write IDR.
- **MAC OCP** (0xb0): `(reg >> 1) << 16 | data`, bit 31 set on write; a read
  writes the address and reads back the low 16 bits, no polling.
- **PHY OCP** (0xb8): the same encoding. A write sets bit 31 and polls
  until it clears; a read writes the address and polls until bit 31 is set
  (the data-valid flag). The internal PHY's standard MII register `r` is
  PHY OCP `0xa400 + 2r`; vendor registers (`0xa4xx..0xbfxx`) are direct.
  Polls are bounded by a register-read count.
- **EPHY** (0x80, PCIe PHY) and **CSI** (0x64/0x68, extended config) have
  the same flag-polled shape. EPHY is written only from rge's fixed
  `mac_r25b_ephy` table, which is a driver constant, not firmware.
- **Reset** (`rge_reset`): clear RXCFG accept bits, set the RXDV gate
  (PPSW 0x08), `CMD |= STOPREQ`, wait for both FIFOs empty (MCUCMD 0x30)
  and for `IM & 0x0103 == 0x0103`, keep only TX/RX enable, then `CMD =
  RESET` and wait (bounded) for the bit to clear. `rge_exit_oob` wraps it
  with the RealWoW/OOB release. A timeout is a refusal, never a retry.
- **Rings.** One queue. Descriptor format v1, 32 bytes each, selected by
  RXCFG bit 24 and MAC OCP `0xeb58` bit 0. TX: `cmdsts` (OWN 31, EOR 30, SOF
  29, EOF 28, TXERR 23, length 15:0), `extsts`, 64-bit buffer address, 16
  reserved bytes. RX: two reserved quadwords, the buffer address at byte
  16, `extsts` at 24 and `cmdsts` at 28 (OWN 31, EOR 30, SOF 25, EOF 24,
  RXERRSUM 20, length 13:0, which includes the CRC). Ring bases are
  0x20/0x24 (TX) and 0xe4/0xe8 (RX); the doorbell is a 16-bit write of 1 to
  TXSTART (0x90). EOR marks the last slot; there is no head or tail
  register, so the CPU can see progress only through OWN.
- **Interrupts.** IMR 0x38 and ISR 0x3c (write-1-to-clear). This backend
  never enables a chip interrupt source, MSI or MSI-X, and keeps INTx
  disabled in the PCI command register; it polls.
- **Link.** PHYSTAT (0x6c): link bit 1, speed bits 10M 0x4, 100M 0x8, 1G
  0x10, 2.5G 0x400, resolved flow control 0x20/0x40. Advertisement is ANAR
  (MII 4), GTCR (MII 9) and the 2.5G bit 0x0080 of PHY OCP `0xa5d4`. Link
  is taken from BMSR (MII 1, read twice); PHYSTAT has been seen stale for
  the whole of a link (0x0493 with BMSR up), so its speed is reported as a
  claim, never as the established speed.
- **Pause.** rge advertises symmetric and asymmetric pause; this backend
  does not. The MAC honours received PAUSE whenever negotiation resolves
  flow control on, and rge has no MAC control that ignores PAUSE on its
  own. Advertising it let a link partner stall TX indefinitely (review F3).

## Mapping onto ABSD

The backend follows the I219 split: `rtl8125_pci::admit` judges config
space before any MMIO or config write; `rtl8125.rs` is register logic over
an `Io` trait, host-tested with a fake device; `rtl8125_device.rs` owns the
PCI claim, the uncached BAR mapping (`mmio::map`), the static DMA memory and
the boot entries. Since lane 2 it is also a `nic_device` backend behind the opt-in
option word `net-rtl8125` (with `net` or `net-probe`); every other boot
keeps the 82540 or `net-i219` exactly as before. Each stage is a separate command-line mode word
(`rtl8125-probe`, `rtl8125-phy`, `rtl8125-loopback`) that runs on the BSP
before storage, SMP or user space and ends the boot, like `i219-init`.

## DMA custody

- **Before S3 no DMA exists.** Admission records the command register as
  firmware left it. OVMF hands the function over with bus mastering on, so
  the backend clears it, and checks it reads back clear, before its first
  MMIO access. S1 and S2 never set it. Memory decode is turned off at release
  only if ABSD turned it on.
- **Memory.** Descriptor rings and buffers are page-aligned statics in the
  identity-mapped kernel image. Their physical address is their address,
  and under VFIO it is the IOVA QEMU mapped. No user address ever reaches a
  descriptor. A custody word (`rtl8125_ring::Custody`, host-tested)
  records who owns them: the kernel, then the device (armed), then
  quarantined for the rest of the boot (released). Armed memory never goes
  back to the kernel.
- **Arming (S3).** Rings are built with OWN bits, base registers written and
  the chip configured while bus mastering is still off. Bus mastering is set
  last, then TX/RX enable, then the TXSTART doorbell.
- **Containment admission (#111).** Bus mastering is set only inside the
  declared externally contained envelope (`rtl8125_pci::containment`): the
  CPUID hypervisor bit, KVM's CPUID signature and QEMU q35's host bridge
  (8086:29c0), which is what reference_host's `absd-vfio-guest` presents. The
  admission is structural: the check returns a
  `dma_policy::VmEnvelopeObserved` token (crate-private constructor; CPUID
  is read inside the library), the driver arms only through
  `dma::arm_in_vm` with it, and `dma::arm` refuses `dma_policy::RTL8125`
  without it (`witness-missing`). The token proves that ABSD's
  VM-environment check passed; it does not authenticate the hypervisor.
  Those three signals are compatibility signals, not an enforceable
  security boundary: a hostile or emulated platform can present all three.
  RTL8125 DMA trust in a VM rests on a declared operating assumption, an
  honest KVM host whose IOMMU contains the passthrough device; ABSD detects
  that environment but does not verify it, and the host's IOMMU is not ABSD
  enforcement. On bare metal RTL8125 is Unavailable unless ABSD's own AMD-Vi
  contains it. That containment path has not yet run on any
  RTL8125. In that path the envelope is not consulted, custody moves at
  exposure, and bare metal skips the COM2 check because the read-back is of the
  physical register. The DMA surface's four parts each start on their own page
  in every boot. What is
  gated is DMA: in the NIC, S3 and wire modes the check runs after
  identification (whose only writes are OCP read commands) and before chip
  init, ring construction and MAC configuration, and `arm` checks again
  before bus mastering is set. Anything else, a physical boot in
  particular, is refused there (`NIC UNAVAILABLE Rtl8125(Uncontained(..))`,
  `RTL8125 LOOPBACK REFUSED Uncontained(..)`). Not gated: the S1 probe,
  which only identifies (reads and OCP read commands) and releases; and the
  S2 PHY and link-diagnostic modes, which initialise the chip and PHY with
  bus mastering off and never arm it. This shows that the expected
  compatibility signals of such a VM were observed (not that the boot
  really runs in one, nor that the host's IOMMU confines the function): that is
  the external precondition, and the evidence label is reference_host-vfio. No
  option word skips it.
- **Ordering admission (re-review 3, owner option 1 on #109).** Before
  any DMA-mode chip work the driver finds PCIe Device Control through a
  bounds-checked walk to the PCI Express capability and, if Relaxed
  Ordering (bit 4) or No Snoop (bit 11) is set, writes it back with only
  those bits cleared (every other Device Control bit as read; Device
  Status, write-one-to-clear, written as zero) and reads it back
  (`rtl8125_pci::disable_ordering`); either bit still set refuses DMA.
  Under VFIO that is the guest's view, so the guest then waits (60 s,
  bounded) on COM2 for the run harness: reference_host's `go-agent.py` reads the
  physical register (`setpci -s 02:00.0 CAP_EXP+8.w`, read-only) and
  answers `G` only if both bits are clear there; no harness, a timeout or
  any other answer refuses (`PhysicalCheck(..)`). `arm` re-reads Device
  Control immediately before setting bus mastering. On reference_host the register
  is 0x203f (Relaxed Ordering on, its reset default); the guest's write
  reached the physical register (0x202f before the go and during the run),
  and every guest teardown restored 0x203f, so nothing assumes the bit
  survives a reset. All DMA evidence before this change (the original lane
  and corrective rounds 1 to 3) ran with Relaxed Ordering enabled; this
  change does not validate those runs retroactively.
  The physical check is trusted experimental apparatus and the claim holds
  only for that workflow (`run-dma.sh`): a fresh, exclusive COM2 channel
  created for one guest run, the correct helper (`go-agent.py`, which
  sends `G` only on a successful, timely, well-formed `setpci` read with
  both bits clear), 02:00.0 being the function assigned to the guest, and
  no other writer changing host configuration between the helper's read
  and the arm. The guest cannot tell a fresh `G` from a stale, delayed or
  corrupted one (no request identity, no UART error check); draining COM2
  first is hygiene, not freshness. Robustness against a stale or corrupt
  `G` is unestablished.
- **Before identification** only the PCI-side fence is touched: a function
  whose TXCFG names another revision, or whose register window reads all
  ones, gets no 8125B write at all; bus mastering is cleared and decode
  restored.
- **A confirmed stop is not quiescence.** A reset (`rtl8125::settle`) whose
  stop request leaves either FIFO not empty, or the idle indication absent,
  is retried once; still unconfirmed is `StopUnconfirmed`. Bring-up then
  refuses before anything is armed, and a release that ends that way
  quarantines the memory. rge treats both waits as non-fatal; on reference_host a
  bring-up over undrained FIFOs put a received frame outside its offered
  buffer (review ps-1, corrective c03). What a confirmed stop shows is only
  what the chip reports about its own FIFOs and engine: it does not show
  that a write the chip already issued has reached memory, and nothing in
  ABSD drains or excludes such a write.
- **Diagnostic release** (S3, wire, every exit path including halt and
  panic through `exit_qemu`): IMR = 0 and ISR acknowledged; RX accept bits
  cleared; STOPREQ and bounded FIFO-empty and idle waits; TX/RX enable
  cleared; soft reset, confirmed as above; only then the ring base
  registers cleared. Then bus mastering is cleared and must read back
  clear. Whatever that showed, the memory becomes `Quarantined` for the
  boot: nothing is scrubbed, reused or returned (re-review 2; a write
  already issued could land after any stop ABSD can observe). If the stop
  was confirmed and bus mastering read back clear, results are inspected,
  and only from descriptors the chip handed back (`rtl8125_ring::
  inspectable`: offered and OWN clear); status words of all descriptors
  are read. The argument for reading such a
  buffer: the chip writes a frame's data before writing its descriptor
  back, both are posted writes from one function, and PCIe keeps posted
  writes in order unless Relaxed Ordering is enabled; arming requires it
  (and No Snoop) disabled in Device Control, as above. A descriptor
  still OWN, or a slot still offered, is counted; its status word is
  read, its buffer is not, and it is never reclaimed. If the stop was not confirmed, nothing is read. The stop at `exit_qemu` is an attempt; its
  result is logged (`RTL8125 SHUTDOWN attempted ...`), it changes nothing
  else.
- **The NIC never gives memory back.** Its rings are pinned for the boot;
  on any fault the stop and fence are attempted and the rings are marked
  quarantined whatever the stop showed.
- **Firmware-left bus mastering (physical-support blocker).** The dma seam
  mediates new Bus Master Enable sets only. Controlling future grants does
  not establish control over DMA authority exercised before the kernel
  arrived: functions firmware left with bus mastering on stay outside
  containment in normal boots (`dma-report` lists them as `DMA INHERITED`).
  Only the AMD-Vi test boots close them; production boots do not. This
  blocks any physical containment claim.
- **Inherited bus mastering: report only (owner decision, Option A).**
  Production boots keep reporting firmware-left masters and clear nothing.
  No physical DMA-containment claim is made while inherited bus mastering
  is not adequately controlled. Selective clearing needs its own design,
  based on hardware_fixture's actual hardware and reviewed independently, before any
  physical qualification. The firmware framebuffer is kept, and any
  exception like it must be narrowly justified. Clearing Bus Master Enable
  after kernel entry would not remove the exposure before kernel entry.
- **Limit.** Clearing bus mastering stops new requests. It does not prove
  that a request already issued has completed, and ABSD programs no IOMMU.
  Under VFIO the host IOMMU confines the device to guest memory; on bare
  metal nothing would, which is why bare metal is refused. The statics are
  never handed to another user in this boot, so a late write could only
  land in them.

## Ring state (`net-rtl8125`)

The ring rules are `src/rtl8125_ring.rs`, behind a `Port` trait (descriptor
memory, buffers, ISR, carrier, clock), host-tested against a model of the
chip. The model reproduces what reference_host's 8125B was seen to do (address
clearing on write-back, skipping a refused descriptor after overflow, the
interrupt status bits). It also models one ordering that was never
observed but is not excluded either: a write issued before trouble was
handled that lands afterwards. That modelled write is what rules out
re-offering rings after trouble:

- **Refill.** The chip clears a descriptor's address quadword when it writes
  the descriptor back. Every refill writes the slot's own buffer address and
  a zero extended status, fences, then sets OWN, as rge_newbuf does (review
  F1: refilling only the command word left address 0 in every used slot).
- **Receive.** A descriptor seen done is fenced, then ISR is read; only if
  ISR shows no receive trouble (0x40 FIFO overflow, 0x8000 system error) and
  the frame's FCS is its CRC-32 is it delivered. ISR is read on idle polls too.
- **Descriptor unavailable (0x10) alone is not trouble.** On reference_host-vfio a burst
  raised it with free slots left and every frame intact, and treating it as
  fatal discarded good frames. The bit is cleared, the clear flushed and only then
  the ring checked, so running out while clearing cannot be erased; the frames are
  delivered as usual. It ends the NIC when no slot is left for the chip, because past real
  exhaustion reference_host delivered frames out of order with only this bit set. A slot
  handed back since the last ISR read does not count as left. It also ends the NIC
  with no forward progress: 64 polls in a row with the bit set and no frame. A burst
  that truly fills the ring therefore still ends the NIC for the boot.
- **Receive trouble disables the NIC.** One overflow episode is counted in
  `rx_missed` (a lower bound), the NIC is disabled (`ERROR_IO`,
  `NIC_FLAG_DISABLED`), the stop and fence are attempted and both rings are
  left exactly as they are, quarantined: nothing in them is delivered,
  rebuilt or offered again. The cost: after any receive overrun the NIC is
  dead until the next boot, visibly. The corrective round 1 recovered by
  chip init and re-offering the same rings (corrective x5, c01, c20); that
  was withdrawn because nothing establishes that a write the chip issued
  before the reset cannot land on a re-offered descriptor afterwards and
  pass, FCS and all, as a current frame (re-review 1). Recovery waits for
  an established reset/exclusion contract.
- **Transmit.** `e1000_ring::TxSlots` through a port that rewrites the
  buffer address on every post, keeps error completions, vanished-device
  reads and a stalled clock as faults, and counts a completion with TXERR
  or excessive collisions as `tx_errors` (the I219 counts errored
  completions in `tx_frames`). A collision count alone is a sent frame,
  counted in the ring's `collisions` (as rge does; re-review 3).

What the round-1 experiments showed about overrun (x1-x5, reference_host-vfio, n=1
each), kept for whoever designs recovery: acknowledging ISR alone resumed
reception but left the chip's ring position different from the driver's
(slots skipped, frames delivered out of order); toggling RX enable and
rewriting the ring base did not move the chip's position; a plain
`hw_reset` resynchronised it but, taken during a line-rate burst, twice left
reception dead with ISR clear and the first frame afterwards outside its
buffer; rge's chip init, which also writes PHY registers (BMCR, and the
UPS-resume path), recovered during the burst with the link kept in those
runs. Frames already in the ring when trouble is seen were observed out of
order.

## Skipped because it needs firmware

Firmware is never loaded. These rge steps are skipped and reported in the
serial output:

- `rge_mac_config_mcu` for `MAC_R25B`: the MAC MCU patch table from
  `rtl8125b-2.fw`. rge's preceding step that clears the MCU break-point
  registers (0xfc26..0xfc48) does run, so whatever MCU patch is present is
  disabled, not inherited.
- `rge_phy_config_mcu`: the PHY RAM-code patch table, applied when the PHY's
  RAM-code version (PHY parameter 0x801e) is not 0x0b99. The version is
  read and reported. The rest of `rge_phy_config_mac_r25b` (fixed tuning
  constants) runs.

## Also skipped (not firmware)

PCIe ASPM and ECPM disable in the link control register (QEMU virtualises
link control); the config write at 0x70c (beyond mechanism #1's 256
bytes); and the CSI writes to 0x108 (the AER uncorrectable-error mask) and
0x98, which reach the function's real configuration space through the chip,
around VFIO's config virtualisation. WoL, RSS, multi-queue, VLAN, checksum offload, interrupt
moderation and jumbo frames are not used.

## Reset state

On reference_host the untouched PHY advertises 10/100 after an AC power-on and
2.5G after a warm reset (#109, 2026-10-30). The backend never inherits the
advertisement: S2 writes ANAR, GTCR and `0xa5d4` explicitly and restarts
negotiation. Each run log records the reset that preceded it.

## Observed on reference_host's 8125B (2026-10-30, reference_host-vfio)

Run logs are in `archived-occurrence`; the lane's
`PROGRESS.md` has the details. Each fact comes from one run unless stated.

- **Identity (S1).** TXCFG 0x67100d80 (XID 641), PHY id 0x001cc840, MAC
  xx:xx:xx:xx:xx:xx (redacted) in both IDR and ADDR0/1. OVMF leaves bus mastering on.
- **PHY without firmware (S2).** The PHY RAM-code version reads 0x0000: no
  patch is present and none is applied. Starting from the cold state
  (10/100 advertised), the explicit advertisement gives a 2.5G full-duplex
  link to the r8169 peer, confirmed by `ethtool` on the peer. The PHY reads
  back ANAR 0x1de1 for 0x0de0 written (selector and XNP set by the PHY) and
  GTCR 0x0200 for 0x0300 (1000BASE-T half duplex not supported). The
  advertisement survives VFIO's reset when the guest exits.
- **MAC loopback (S3).** TXCFG LBK = 01 loops frames back inside the MAC:
  8 frames (60 to 1514 bytes) came back byte-exact and none reached the
  wire (tcpdump on the peer). The RX length includes the 4-byte FCS. The
  32-byte descriptor stride holds for both rings. The chip writes a
  completed TX descriptor's `cmdsts` back as zero, so TX completion carries
  no length or error information in this mode. RX `cmdsts` of a good frame
  was 0x034000xx; bit 22 is set but rge does not name it.
- **Controls.** A TX descriptor posted without OWN stops transmission there;
  the descriptors behind it are reported device-owned at release (since
  re-review 2 they are not read or reclaimed; the memory is quarantined). RX buffers offered as
  64 bytes make the chip split each frame across descriptors (SOF and EOF in
  different slots), which the classifier refuses; after that run the stop
  sequence found the FIFOs not empty, and the soft reset still completed.
- **Wire (optional stage, `rtl8125-wire`).** With loopback off and the same
  rings, the 8 test frames reached the r8169 peer byte-exact at 2.5G
  (peer's tcpdump), and the guest received the peer's ARP requests: 64
  bytes each, the peer's 42-byte frame zero-padded to 60 plus a correct
  CRC-32 FCS. PHYSTAT can show a stale speed for a moment after
  negotiation restarts, so this mode waits for three seconds of a steady
  link before arming.
- **State left behind.** S2 and the wire mode leave the PHY advertising
  everything and linked at 2.5G. S3 leaves every speed withdrawn (rge's
  `phy_config` withdraws them and S3 does not re-advertise), so the peer
  sees no link afterwards.

## Lane 2 observations (2026-10-30, reference_host-vfio)

- **Cold start repeated.** On a fresh AC-off boot, S2, S3 and both controls
  reproduced lane 1 exactly: 2.5G at 3.1 s, 8/8 frames byte-exact, and both
  controls failed closed.
- **Warm start, with tuning.** 2.5G at 3.9 s, held for 300 s with no change,
  confirmed every 30 s by the peer's `ethtool`. S3 passed.
- **PHYSTAT after S3: explained and fixed.** Once S3 has withdrawn every
  speed, PHYSTAT reads 0x0493 (LINK and 1000 set while the cable is down).
  After link-up it reads 0x04f3, keeping the stale 1000 bit next to 2500.
  BMSR (second read) follows the cable to within 0.1 s of the peer's
  link-up (run diag-1). Link therefore comes only from BMSR
  (`rtl8125::cable_link`), and PHYSTAT only names a speed when it shows
  exactly one. Why the PHYSTAT bits stick is not established.
- **PHY tuning A/B (warm, one run per set).** With and without rge's fixed
  8125B PHY constants, every measure tied:
  - S2 link time: 3.9 s with, 3.6 s without.
  - Both held 2.5G for 300 s with no change.
  - S3: 8/8 frames byte-exact in both.
  - 2000 sustained wire passes started right after S3: 32008 of 32008
    frames byte-exact at the peer in both, with 0 errors in the peer's
    counters.
- **Integrated (`net-rtl8125`).** The `net-probe` reflector moved 34
  frames, 15 to 1514 bytes, plus a 24-frame back-to-back burst, byte-exact
  through the integrated interface at 2.5G. A 16-slot RX ring dropped 8
  frames of that burst; the ring is now 32 slots, the e1000's size.

## Audit: the three configuration writes this backend leaves out

Owner direction (2026-10-30): leave them out, and do not suppress AER
without a demonstrated need. This section only records what each write
does, so that the decision can be revisited from evidence. Offsets are
placed using the capability list of reference_host's other 8125B (01:00.0, the same
part, read with `lspci -vvv`): PM at 0x40, MSI 0x50, PCIe 0x70, MSI-X 0xb0,
VPD 0xd0; extended: AER 0x100, VC 0x148, DSN 0x168, TPH 0x178, LTR 0x204,
L1 PM substates 0x20c, vendor-specific 0x21c (length 0x100).

CSI (CSIAR 0x68, CSIDR 0x64; 12-bit address) is the chip's own window onto
its configuration space. A CSI write reaches the real register directly,
around both the OS's view and VFIO's config virtualisation.

| Write (rge v1.48) | Register at that offset | Effect | ABSD need |
|---|---|---|---|
| `rge_hw_init`: CSI 0x108 \|= 0x00100000. Comment: "Set PCIe uncorrectable error status" | AER cap + 0x08: **Uncorrectable Error Mask** (status is +0x04, so the comment names the wrong register) | Bit 20 masks **Unsupported Request**: the function stops reporting URs it detects, through AER logging or error messages | None shown. ABSD has no AER handling. No AER message for either function appeared in reference_host's kernel log during any lane run |
| `rge_init`: CSI 0x98 &= ~0x0000ff00, after MAC OCP 0xe032 &= ~3. No comment | PCIe cap + 0x28: **Device Control 2** (bits 15:8). Device Status 2 is at 0x9a | Clears IDO request/completion enable (8, 9), LTR mechanism enable (10), emergency power reduction request (11), 10-bit tag requester enable (12), OBFF enable (14:13), end-end TLP prefix blocking (15) | None shown. These bits belong to firmware and the OS. On 01:00.0 under Linux the byte already reads 0x00 |
| `rge_init`: config 0x70c: bits 29:24 = 0x27. No comment | Extended space, outside every listed capability, so a vendor-defined register of the PCIe core | Not documented. If the core follows the Synopsys DesignWare "port logic" layout, which is **not established for Realtek**, 0x70c is ACK frequency and ASPM control, and the field holds the L0s/L1 entrance latencies. ASPM is disabled on this link (LnkCtl), so the field is probably inert here | None shown. ABSD's mechanism-#1 access cannot reach 0x70c; it would need ECAM or CSI |

**Risk of adding them.**
- **0x108:** hides a whole error class from the platform, which the owner's
  rule forbids without a demonstrated need.
- **0x98:** overrides power and ordering features the platform chose, and
  might raise idle power if LTR had been on.
- **0x70c:** writes an undocumented register.
- **All three:** they bypass VFIO, so on reference_host the host's view of the
  function no longer matches the real register.

**Risk of leaving them out.** Realtek and rge presumably add them to work
around platform trouble: UR noise under AER (0x108), LTR/OBFF interaction
(0x98), and ASPM exit latency (0x70c). None of that was seen. S1-S3, the
wire runs and a 5-minute link hold all ran without the writes. Linux holds
native AER control on reference_host (`_OSC: OS now controls [... AER ...]`), and no
AER error line appeared in the three boots that covered every run.

**Decision support.** Keep them out. Revisit 0x108 only on observed AER
Unsupported Request reports from this function. Revisit 0x98 only if
LTR/OBFF is found enabled and misbehaving; reading DevCtl2 needs no write,
because 0x98 is inside the 256 bytes mechanism #1 reaches. Revisit 0x70c
only with a documented meaning.

## Corrective increment observations (2026-10-30, reference_host-vfio)

Logs in `archived-occurrence`, record in
`PROGRESS-CORRECTIVE.md` there. All warm, n=1 per run unless stated.

- **A full TX FIFO survives guest teardown.** After the old code disabled
  the NIC on a PAUSE-induced transmit timeout, MCUCMD read 0x12 (RX FIFO
  empty, TX FIFO not) in the next guests through two reset attempts, two
  VFIO teardowns (the host resets this function by secondary bus reset) and
  a reset-with-RX-and-TX-enabled attempt with bus mastering off. The old
  code armed over it and lost frame 0's data (c03); this backend refuses
  (`StopUnconfirmed`, then named `NotQuiescent`: `NIC UNAVAILABLE Rtl8125(Chip(NotQuiescent))`) and stays
  refused until the state clears. A warm reboot of the host cleared it
  (c08 -> c09). Draining it with bus mastering on would let the chip fetch
  through a descriptor cached from the previous kernel, which bare metal
  could not contain. This backend no longer stalls in that way (pause is
  not advertised) and quiesces the chip at exit.
- **Pause.** With pause unadvertised, PHYSTAT shows no flow bits and every
  frame of a 1000-frame send went out during a 3 s storm of PAUSE frames
  (quanta 0xffff, ~1/ms) in seven runs (x1-x5, c01, c20).
- **Not established here.** Bare-metal DMA containment (ABSD programs no
  IOMMU; bare metal is refused; this is reference_host-vfio evidence only), a safe
  receive recovery, interrupt mode, the second
  port, the PHY tuning decision and a corrected cold start (needs an owner
  AC-off).

## Next milestone: interrupt-driven operation (design note, not built)

The `net-rtl8125` backend polls. To move to interrupts:

- **Vector.** One MSI-X vector on the BSP, as the bounded `xhci-controller`
  boot does (`src/xhci_interrupt.rs`, `src/pci_interrupt.rs`). INTx stays
  masked. The MSI-X table is BAR4. VFIO traps it and the host programs the
  real entry, so the guest-side code is the ordinary path.
- **Sources.** IMR (0x38) enables RX_OK, RX_ERR, TX_OK, TX_ERR, LINKCHG,
  RX_DESC_UNAVAIL and SYSTEM_ERR. That is rge's `RGE_INTRS` without
  PCS_TIMEOUT, and without rge's simulated moderation through TIMERINT0.
- **Handler.** Mask IMR to 0, read ISR and write the same value back (it is
  write-1-to-clear), and defer the ring work to the existing poll routines,
  then unmask. No ring access happens in interrupt context. LINKCHG
  re-reads `cable_link` (BMSR); it never trusts PHYSTAT's link bit.
  SYSTEM_ERR disables the NIC through the same stop and bus-master-off
  path as today. rge reinitializes the chip instead, which this backend
  cannot do because its rings are pinned.
- **Release.** IMR 0 and the ISR acknowledged before the stop sequence
  (already the order in `quiesce`), then the vector masked in the MSI-X
  table before bus mastering is cleared.
- **Tests.** A host test of the handler's mask, acknowledge and unmask
  order over the fake `Io`. A reference_host run that counts interrupts against
  frames and checks that no interrupt arrives after release.
